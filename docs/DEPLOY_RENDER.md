# Deploying on Render + MongoDB Atlas

This is the Option C deployment: one Docker web service on Render, MongoDB
Atlas for metadata, and a Render persistent disk for private resume storage.

```
Browser
   │  HTTPS (Render-managed certificate)
   ▼
Render web service ── Express (serves /api and client/dist)
   │
   ├── MongoDB Atlas .......... users, resumes, sessions, edits, export records
   └── /app/storage ........... original DOCX files, exports, previews
```

The repository already contains [`render.yaml`](../render.yaml), which defines
the service, disk, health check, and non-secret environment variables.

---

## 1. Create the MongoDB Atlas database

1. Create a free **M0** cluster.
   - Provider: **AWS**
   - Region: **us-west-2 (Oregon)** — matches `region: oregon` in `render.yaml`
     so app-to-database latency stays low. Pick a different matching pair if you
     change the Render region.
2. **Database Access → Add New Database User**
   - Use password authentication and a strong password.
   - Prefer a password without URL-reserved characters. If it contains
     `@ : / ? # [ ] %`, URL-encode it in the connection string
     (`@` → `%40`, `:` → `%3A`, `/` → `%2F`, `#` → `%23`).
3. **Network Access → Add IP Address**
   - Render's outbound IPs are dynamic, so the practical option is
     `0.0.0.0/0`. Atlas still requires TLS and a valid username/password.
   - If your Render plan provides static outbound IPs, allowlist those instead.
4. **Connect → Drivers → Node.js**, then add the database name to the path:

   ```text
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/ai_resume_tailor?retryWrites=true&w=majority
   ```

   The app creates its collections automatically on first use. No migration step
   is required.

> Do not reuse this cluster for unrelated data: the app applies its own
> retention cleanup (`RETENTION_DAYS`) and deletes expired resumes and exports.

## 2. Push the project to GitHub

Render deploys from a Git repository. If this project is not a repository yet:

```bash
cd ai-resume-tailor
git init
git add .
git commit -m "AI Resume Tailor"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

Before pushing, confirm these are **not** committed:

```bash
git status --short
```

`.gitignore` already excludes `node_modules/`, `client/dist/`, `dist/`,
`storage/`, `.env`, and `.env.*`. Never commit real API keys or uploaded resumes.

## 3. Create the Blueprint on Render

1. Render Dashboard → **New → Blueprint**.
2. Connect GitHub and select the repository.
3. Render reads `render.yaml` and shows the service.
4. When prompted for the `sync: false` variable, paste **`MONGODB_URI`** from
   step 1.
5. Click **Apply**.

`JWT_SECRET` is generated by Render (`generateValue: true`). `CLIENT_ORIGIN` is
not in the blueprint on purpose: the server falls back to Render's
`RENDER_EXTERNAL_URL`, so the first deploy works without copying the URL around.
Set it explicitly only when you add a custom domain (step 6).

### Manual setup instead of a Blueprint

If you prefer the dashboard:

| Setting | Value |
| --- | --- |
| Type | Web Service |
| Runtime | Docker |
| Dockerfile | `./Dockerfile` |
| Health check path | `/api/health` |
| Instance count | **1** |
| Disk name / mount / size | `resume-storage` / `/app/storage` / 5 GB |
| Plan | Starter or higher (disks are not available on Free) |

Environment variables:

```env
NODE_ENV=production
JWT_SECRET=<32+ random characters>
COOKIE_SECURE=true
TRUST_PROXY=true
MONGODB_URI=<Atlas SRV URI>
STORAGE_DRIVER=local
STORAGE_DIR=/app/storage
MAX_UPLOAD_MB=10
RETENTION_DAYS=30
CLEANUP_INTERVAL_MINUTES=60
RATE_LIMIT_MAX=300
AUTH_RATE_LIMIT_MAX=20
HEAVY_RATE_LIMIT_MAX=30
UPLOAD_RATE_LIMIT_MAX=20
AI_PROVIDER=heuristic
LOG_LEVEL=info
```

Do **not** set `PORT`. Render injects it (default `10000`) and the server binds to
it automatically.

## 4. Watch the first deploy

The build runs `npm ci`, builds the React client, installs production
dependencies, and creates the runtime image. Expect roughly 3–6 minutes on the
first build.

Render deploys the service only after `/api/health` returns HTTP 200. That
endpoint returns 503 until MongoDB is connected (`healthRoutes.js:13`), so a
healthy check proves the database connection works.

Check the logs for:

```text
AI Resume Tailor server started  { port: 10000, environment: 'production', ... }
```

If the process exits immediately, the log message names the invalid setting —
the configuration schema refuses weak secrets, wildcard origins, an LLM provider
without a key, or incomplete S3 settings.

## 5. Verify the deployment

```bash
curl -s https://<service>.onrender.com/api/health
```

Expected shape:

```json
{
  "success": true,
  "data": {
    "status": "ok",
    "database": "connected",
    "storage": "local",
    "renderer": { "available": false, "renderer": "none", "previewMode": "html" },
    "aiProvider": "heuristic"
  }
}
```

Then exercise the real workflow:

1. Register an account.
2. Upload a DOCX resume.
3. Paste a job description and start the analysis.
4. Accept, reject, and edit at least one suggestion.
5. Export and download the DOCX.
6. Open the downloaded file in Word and confirm the layout.
7. Restart the service (Render Dashboard → Manual Deploy → Restart), then
   re-download the latest export. It must still exist — that proves the disk is
   mounted and persistent.

## 6. Custom domain

1. Render Dashboard → the service → **Settings → Custom Domains**.
2. Add `resume.example.com` and create the DNS record Render shows.
3. Add/override the environment variable:

   ```env
   CLIENT_ORIGIN=https://resume.example.com
   ```

4. Redeploy.

Without step 3, `CLIENT_ORIGIN` still points at the `onrender.com` URL and
state-changing requests from the custom domain are rejected with
`403 ORIGIN_NOT_ALLOWED`. That check exists because the session cookie is sent
with every mutation (`errorHandler.js:28`).

## 7. Choosing an AI provider

The default `AI_PROVIDER=heuristic` runs entirely locally: no API key, no
external calls, and only conservative reordering and verb swaps.

To use a real LLM, add these in **Environment** and redeploy:

```env
AI_PROVIDER=openai            # or anthropic
AI_API_KEY=<secret>
AI_MODEL=gpt-4.1-mini         # must match the provider
AI_BASE_URL=                  # optional OpenAI-compatible gateway
```

Notes:

- `AI_PROVIDER` other than `heuristic` without `AI_API_KEY` is a startup error by
  design.
- Store the key as a Render secret environment variable; never in the repo.
- Resume text sent to the provider is redacted (emails, phone numbers, URLs,
  LinkedIn) and resume content is never logged.

## 8. PDF previews (optional)

The default image has **no LibreOffice**, so exports get an honest HTML content
preview plus a warning that pagination was not visually verified.

Render's dashboard and Blueprint do not expose Docker build args, so the simplest
way to enable PDF previews is to change the default in `Dockerfile`:

```dockerfile
ARG INSTALL_LIBREOFFICE=true
```

Then redeploy. Expect a much larger image and a slower build. Use at least the
**Standard** plan (2 GB) because LibreOffice rendering is memory-hungry, and
confirm `/api/health` reports `"renderer": "libreoffice"` with
`"previewMode": "pdf"`.

## 9. Backups

Render's disk and Atlas metadata must be backed up **together**. A database row
without its DOCX file is useless, and an orphaned file cannot be mapped back to a
user.

- **Atlas M0** does not include automated backups. Schedule `mongodump` from a
  trusted machine:

  ```bash
  mongodump --uri="mongodb+srv://USER:PASS@cluster.mongodb.net/ai_resume_tailor" \
            --archive=ai_resume_tailor-$(date +%F).gz --gzip
  ```

  Upgrade to a tier with continuous backups if this holds real user data.
- **Render disk**: copy `/app/storage` periodically (Render Shell on paid
  instances):

  ```bash
  tar -czf /tmp/storage-$(date +%F).tgz -C /app storage
  ```

  Download it, or move the whole workload to `STORAGE_DRIVER=s3` with a private
  bucket and versioning.
- Test a restore before you need one.

## 10. Costs and limits

Approximate, at the time of writing — confirm on Render's pricing page:

| Item | Cost |
| --- | --- |
| Render Starter instance | ~$7/month |
| Persistent disk | ~$0.25/GB/month (5 GB ≈ $1.25) |
| Render Standard instance | ~$25/month |
| Atlas M0 | free |

Free-tier caveats:

- **No persistent disks.** Without a disk, use `STORAGE_DRIVER=s3`
  (Cloudflare R2, AWS S3, Backblaze B2). Otherwise uploads vanish on restart.
- Services spin down after inactivity; the first request afterwards is slow.
- 750 instance hours/month.

Operational limits that apply on any plan:

- **One instance only.** Analysis and export jobs run in-process. Multiple
  replicas each run their own worker with no shared queue.
- A persistent disk forces a brief restart during deploys (no zero-downtime
  swap).
- There is no PDF renderer unless you build LibreOffice into the image.

## 11. Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `403 ORIGIN_NOT_ALLOWED` on register/login | `CLIENT_ORIGIN` does not match the browser origin (common after adding a custom domain) | Set `CLIENT_ORIGIN` to the exact `https://` origin and redeploy |
| Health check stays failing, logs show Mongo timeout | Atlas network access or wrong URI/password | Allowlist `0.0.0.0/0`, URL-encode the password, keep `?retryWrites=true&w=majority` |
| App exits with `Invalid environment configuration` | Missing/weak `JWT_SECRET`, LLM provider without `AI_API_KEY`, incomplete S3 settings | Read the listed issue in the log and correct it |
| Upload returns 500, logs show `EACCES` | Mounted disk is root-owned | Confirm the image uses the bundled entrypoint; it chowns `STORAGE_DIR` then drops to `node` |
| Login succeeds but the next request is unauthenticated | `COOKIE_SECURE=false` on HTTPS, or proxy not trusted | Set `COOKIE_SECURE=true` and `TRUST_PROXY=true` |
| Rate limit hits too early | All requests look like one IP | Keep `TRUST_PROXY=true`; raise `RATE_LIMIT_MAX` only if needed |
| Export fails validation | Generated DOCX did not match approved edits | The export is marked failed and the file is withheld; retry after reviewing changes |
| Build fails at `npm ci` | Lockfile out of date | Run `npm install` locally, commit `package-lock.json`, push |
| Free tier loses uploads after idle | No persistent disk | Add a disk (paid) or switch to S3 |

## 12. Security checklist for this deployment

- [ ] `JWT_SECRET` is generated by Render or is 32+ random characters
- [ ] `NODE_ENV=production`, `COOKIE_SECURE=true`, `TRUST_PROXY=true`
- [ ] `CLIENT_ORIGIN` is the exact public HTTPS origin (no wildcard)
- [ ] Atlas user is dedicated to this app, with a strong password and TLS
- [ ] Storage disk is private; nothing is exposed as a static directory
- [ ] `RETENTION_DAYS` matches your privacy policy
- [ ] AI keys live in Render environment variables, not in Git
- [ ] Backups of Atlas and `/app/storage` are scheduled and restore-tested
- [ ] Only one app instance is running
